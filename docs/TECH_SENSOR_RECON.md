## 1 证据与复跑

`spike/cdp-test.mjs` 起本地静态服务 → 无头 Chrome → CDP `DeviceOrientation.setDeviceOrientationOverride` 注入姿态 → 断言页面逻辑：

```
PASS  页面加载 + probe 就绪
PASS  localhost 属安全上下文  — secure=true
PASS  DeviceOrientationEvent 存在  — api=true permFn=true
PASS  点击授权按钮后进入监听态  — perm=granted
PASS  CDP 方向注入 → 页面收到 deviceorientation  — events=1
PASS  基准可记录（直立/平放姿态自适应）
PASS  超过阈值触发一次（一次倾斜=一次结算）  — fires=1 dir=down mag=22
PASS  回正保持 80ms 后重新武装（设计稿口径）  — armed=true fires=1
PASS  第二次倾斜可再触发（gamma 轴）  — fires=2 dir=right
PASS  阈值下抖动不误触  — fires=2
PASS  45° 斜倾不触发（轴比 1.0 < 2.0）  — fires=2 ratio=1
PASS  持续倾斜不连发  — fires=3→3
PASS  rAF 循环在跑（本机无头 Chrome）  — fps=123
PASS  触发日志可读（含方向与幅度）  — log=9 行
PASS  采样频率已统计  — hz=1
15/15 PASS
```

诚实说明三点：

- `fps=116` 是无头模式的 rAF（无 vsync 上限），**不是手机帧率**，只证明渲染循环在跑。
- `hz=1` 是因为 CDP 只在姿态值**发生变化**时推一个事件、同值不重发；真机是连续流（50–100Hz），频率必须在手机上读（见 §7）。
- 因此“回正保持 80ms”这类**依赖连续事件**的规则，无头只能验证逻辑分支走得通，真实时长仍要真机确认。

## 2 传感器方案（实现阶段直接照这个做）

### 2.1 用 `deviceorientation`，不用 `devicemotion`

| | deviceorientation | devicemotion |
|---|---|---|
| 数据 | 融合后的姿态角 beta/gamma（度） | 含重力的原始加速度（g） |
| 噪声 | 低，系统已融合 | 高，手抖直接进数据 |
| 结算用 | 直接得倾斜方向 | 需低通滤波再判方向 |

结论：**主用 `deviceorientation` 的 beta/gamma**，按“相对基线”判方向。`devicemotion` 不接（接了只会引入抖动和第二套权限，见 §3）。

### 2.2 阈值口径（度是唯一口径，g 只作对照）

设计稿 v0.2 与实现统一用**度**：`TRIGGER_DEG = 20.5`、`RELEASE_DEG = 5.7`、回正保持 **80ms**、`AXIS_RATIO = 2.0`（无单位）。`DeviceOrientationEvent.beta/gamma` 原生就是度、且已过系统重力融合，直接用，**不要反算 g**。

g 只在物理直觉和验收时做等价说明（`g = sin θ`），不参与实现：

| 用途 | 度（唯一口径） | g 等价（仅参考） |
|---|---|---|
| 触发倾斜 | ≥ 20.5° | 0.35g |
| 回正 | ≤ 5.7° | 0.10g |
| 方向轴比 | 2.0（无单位） | 同左，等价于偏离主轴 ≤26.6° |

**边界**：幅度接近 0 时直接不触发（先判幅度、再判轴比）；轴比用 `主轴 / 副轴`，副轴为 0 时视为“方向明确”取无穷大，不要做除零。轴比在角度域算即可，小倾角下与 g 域判据等价。

### 2.3 必须做基线校准

同一个“竖直拿手机”的姿态，不同设备/拿法读数差很远（直立时 beta 常见 ≈90°，平放在桌上 ≈0°）。所以：

1. 进入关卡时取 200–300ms 均值当**基线**（探针里的“设为基准”就是这个）；
2. 之后只判 `β−基线β`、`γ−基线γ`；
3. 校准值存 `localStorage`，重开不用再校。

### 2.4 方向符号

物理方向与 beta/gamma 的符号关系依赖拿法和设备，**不要凭推理定**。探针页留了 `FLIP = {x:1, y:1}`（[index.html:96](../spike/sensor-probe/index.html)），真机上试一次，反了就改 `-1`，游戏代码沿用同一开关即可。

### 2.5 触发状态机（已在探针里跑通）

```
armed --(幅度≥20.5° 且 轴比≥2.0)--> fire, waiting
waiting --(幅度≤5.7°，连续保持 80ms)--> armed
```

实现要点：

1. **触发只在状态机里发生一次**，渲染层拿到的是“一条移动指令”，不是连续重力。这样“倾斜一次 = 一次不可撤回的结算”在代码层也成立，撤销才有意义。
2. **不要叠加时间冷却**。曾经在探针里用 140ms 冷却兜底，和“回正 80ms 重新武装”是两套节流：玩家回正 80ms 后立刻再倾，物理上该算一步，冷却会把它吞掉。现在只留状态机。
3. 探针页按设计稿口径实现（20.5° / 5.7° / 轴比 2.0 / 80ms），阈值与轴比都可现场拖动，用来确定真机手感。

## 3 安卓 Chrome 限制清单（真机必查）

1. **无授权弹窗**：安卓 Chrome 读方向不需要用户点按（与 iOS 不同）；但**必须安全上下文**，http 直接静默无数据。
2. **后台/锁屏停发**：切后台、锁屏后事件停止。恢复时必须重置 `armed` 并丢弃暂停期样本，否则会拿旧姿态误触发一步。
3. **屏幕旋转**：转横屏后 beta/gamma 语义变化。建议锁竖屏（CSS 布局 + 横屏提示遮罩）；`screen.orientation.lock()` 只有安卓 Chrome 全屏时可用，别依赖。
4. **事件频率**：真机约 50–100Hz（机型/省电模式有差异）。够用——阈值判定每帧一次都嫌多。
5. **无陀螺仪设备**：极少数。兜底：启动 2s 内无任何事件 → 提示“设备不支持重力感应，请换设备”。
6. **省电/低电量模式**：可能降频；不影响回合制玩法。
7. **页面可见性**：`document.visibilitychange` 时暂停动画并重置状态机。

## 4 GitHub Pages 部署方案

### 4.1 仓库结构（建议）

```
gravity-sokoban/            ← 仓库根 = Pages 站点根
  index.html                ← 游戏入口（单文件起手，后续可拆 assets/）
  docs/                     ← 设计文档（可一起传，不影响访问）
  spike/                    ← 探针页（可传，路径 /spike/sensor-probe/）
```

项目页地址形如 `https://<user>.github.io/gravity-sokoban/`，**资源引用一律用相对路径**（不能以 `/` 开头），否则子路径 404。探针页当前是单文件、零外部请求，天然满足。

### 4.2 步骤（需要用户账号，我不代跑）

1. GitHub 新建仓库 `gravity-sokoban`（**公开**；免费版 Pages 不支持私有仓库）；
2. 本地推上去；
3. Settings → Pages → Source: `Deploy from a branch` → Branch `main` / 目录 `/ (root)` → Save；
4. 等 1–2 分钟，访问 `https://<user>.github.io/gravity-sokoban/`；
5. 手机 Chrome 打开同一 URL 验证（见 §6）。

### 4.3 两个坑

- **缓存**：Pages 默认缓存约 10 分钟。周末改版后用 `?v=2` 之类的查询串强制刷新，别等。
- **HTTPS 是自动的**：Pages 自带证书，满足传感器对安全上下文的要求——这也是选它而不是“随便找个静态托管”的原因。

## 5 帧率与性能

结论：**不是风险，但“60fps”本身不是这个游戏的需求。**

- 玩法是回合制：一次倾斜 → 一次结算 → 150–250ms 滑动动画。掉一帧看不出来。
- 渲染规模：8×8 网格 + 十几个箱子。Canvas2D 或 DOM/CSS transform 都远低于 16.7ms/帧。
- 真正需要关注的是**传感器回调里不要做布局/重绘**：阈值判定只存值 + 置标志，动画在 rAF 里统一推进。
- 无头 Chrome 的 113–117fps 是“无 vsync”读数，**不能作为手机 60fps 的证据**；手机上用探针页自带的 fps 读数确认一次即可（§6 第 7 步）。

## 6 真机 10 分钟验证协议（周末前做一次）

1. 手机 Chrome 打开部署 URL（必须 `https://`）；
2. 点“启用重力传感器”；
3. 看 beta/gamma 有数、事件/秒 > 0 —— 若一直“–”，说明不是安全上下文或设备无传感器；
4. 竖直拿稳，点“设为基准”；
5. 向右倾斜约 30°，箭头应变 →、日志出现 `FIRE #1 → right`；若反了，改 `FLIP.x = -1`；
6. 快速左右抖 3 秒 —— 触发次数不应增加；
7. 保持倾斜 2 秒 —— 只应触发 1 次；
8. 回正后**停 0.2 秒**再倾斜 —— 应能再触发；快速“回正-马上倾”不应连环触发；
9. **斜着 45° 倾（对角）—— 不应触发**（轴比 1.0 < 2.0）；若你觉得“端不平也滑不动”太苛刻，把轴比拖到 1.6 再试，哪个顺手报哪个；
10. 读“rAF 帧率”；
11. 把页面截图 + “复制诊断”的 JSON 发回来，我据此定阈值。

> 第 5、8、9 条就是设计稿触发模型的真机验收；日志会写明每次 `FIRE #n` 的方向与幅度，截图即可复算。

## 8 给设计/实现的约束（写进 GAME_DESIGN.md 建议）

1. 阈值只存一套度数（20.5° 触发 / 5.7° 回正 / 轴比 2.0），不要再并存 g 口径；
2. **不要叠加时间冷却**：回正 80ms 重新武装已经是唯一节流，再加冷却会吞掉合法快倾；
3. “倾斜一次 = 一条指令”，传感器回调不直接驱动渲染；
4. 校准必做且持久化；
5. 失焦/旋转/恢复要重置状态机；
6. 撤销粒度 = 最近一次倾斜，挡块位置一起回退（与 Design §5 一致）；
7. 部署形态：仓库根 `index.html`，全相对路径，无 CDN。
