# 《重力推箱子》游戏设计文档 v0.2

状态：**待评审**（评审通过前不写游戏代码）
平台：手机网页（GitHub Pages），主用机安卓 Chrome
目标：周末可玩的 MVP
记号约定：本文所有阈值一律用**角度（度）**。读 `DeviceOrientationEvent` 的 `beta`/`gamma`，它本身就是度、且已由系统融合重力解算，不读 `DeviceMotionEvent` 的加速度（后者混入手部运动的线性加速度，晃一下就有噪声）。g 只作物理等价说明：`g = sinθ`，0.35g ⇔ 20.5°、0.10g ⇔ 5.7°。**代码里只存一套度阈值，不并存两套。**

## 0. 一页版

**倾斜手机一次，所有箱子同时沿重力方向滑到撞上东西为止；你只有一个不受重力、可以随手拖动的挡块。**

- 没有玩家角色，没有推。你唯一能动的只有那 1 个挡块。
- 一次倾斜是**一整步**：所有箱子同时结算，倾完必须回正才能再倾。
- 箱子撞墙停、撞箱停、撞挡块停。箱子不会推箱子。
- 所有箱子同时停在目标格 = 赢。目标不锁定，箱子会被推走。
- 一次倾斜里挡块最多只救得了一条行/列——它只占一格。这条限制是整个游戏难度的来源。

体验一句话：不是"把箱子推到洞口"，是"算好这一倾之后每个箱子会停在哪，再决定挡块放哪"。

## 1. 目标与非目标

### 1.1 目标
用最小实现验证一个核心手感：**一次倾斜 = 一次不可撤回的承诺**，玩家靠预演而不是靠反应。
沿路要跑通：传感器触发 → 整盘结算 → 挡块拖拽 → 撤销/重开 → 12 关。
本次不追求长内容，追求"能玩、能测、能改"。

### 1.2 非目标（本版不做）
账号、后端、排行榜、商店、多语言、关卡编辑器、星级评分、自动死局检测、音效库、动画骨骼。
多挡块、箱子互推、坑洞、敌人、计时、斜坡重力。

## 2. 核心规则

### 2.1 网格与实体

- 直角网格，整数格 `(x, y)`，`x` 右、`y` 下。**所有关卡统一 7 列 × 9 行**（地图外一律视为墙）。
- 格子只有三种：`WALL`（不可进入）、`FLOOR`、`GOAL`（目标格，可进入）。
- 实体只有两种：**箱子**（受重力，可被挡停）、**挡块**（不受重力，玩家拖动）。
- 每关箱子数 == 目标格数，加载时校验；不相等视为关卡非法（开发期直接报错）。

### 2.2 一次倾斜的结算

方向 `d` 为上下左右之一。**这不是实现细节，是规则定义本身**：

1. 对每个箱子算 `t` = 沿 `d` 到地图边缘的格数。
2. 按 `t` **升序**处理（贴着目的地墙的先动）；`t` 相同按 `(y, x)` 升序（只影响日志，不影响结果）。
3. 每个箱子沿 `d` 逐格试探，下一格是 `WALL`、是**本次结算中已停下的箱子**、或是挡块，就停在当前格。
4. 处理完最后一个箱子，得到新状态。

**为什么这样对**：同一方向上箱子不能互相超越，所以"离目的地最近的先走"与"全部同时滑动"逐格等价，而且天然处理"前箱让开、后箱跟进填满"。
反方向遍历（从后往前）会错：后箱会撞到前箱的**旧位置**提前停下。
结论：一趟升序遍历就是规则本身，**不需要**迭代求解或多轮模拟。

**明确禁止**：箱子推箱子、箱子被推出地图、一次倾斜里箱子走两段。

### 2.3 挡块

- 全图**恰好 1 个**，占 1 格，**不受重力**，任何倾斜都不移动它。
- 玩家可把它**拖到任意合法空格**：地图内、非 `WALL`、非箱子格。目标格允许（该格视为未完成）。
- **拖动是"直接落到目标格"，不模拟手指路径**：不检查中间是否被箱子或墙挡住。
  这条是刻意选择：让挡块永远不会被围死，也让"挡块位置"不进入任何需要寻路的状态。
- 非法落点：拖动中预览标红，松手弹回原位，**不改棋盘、不消耗任何东西**。
- 拖动只能在静止态进行（结算动画期间输入锁定）。
- 挡块不可被推动：箱子撞上就停在相邻格。
- **拖拽不限次数、不计步**：步数只统计倾斜。撤销语义见 §3.6。

### 2.4 胜负

- **胜利**：一次结算的动画播完后判定，箱子数 > 0 且每个箱子都在目标格上（箱子数 == 目标格数由 2.1 保证）。
  动画中途不弹胜利。挡块压在目标格上不算完成。
- **失败**：**没有失败**。无计时、无步数上限、箱子不可能出界。
- 不提供自动死局检测。理由见 §4.4 实测：绝大多数局面瞎按也死不了，代价只是变慢；撤销/重开随时可用，做死局检测的收益不抵误报代价。

### 2.5 三个例子

以下三个例子都用校验器实算过（`tools/examples.py`），不是手画的。

**例 1：同向箱子只会整体平移，最前面的不会被挤出边界。**
```
倾斜前              向右倾
#######            #######
#.BBB.#      →     #..BBB#
#.....#            #.....#
#######            #######
```
箱子 (2,1)(3,1)(4,1) → (3,1)(4,1)(5,1)。最前的箱子先走、后箱跟进填满，整队右移一格。

**例 2：一个挡块同时定住两个箱子。**
```
倾斜前              向下倾（挡块已放在 (3,6)）
#######            #######
#..B..#            #.....#
#..B..#            #.....#
#.....#      →     #.....#
#.....#            #..B..#
#..K..#            #..B..#
#.....#            #.....#
#######            #######
```
箱子 (3,1)(3,2) → (3,4)(3,5)。前箱停在挡块正上方 (3,5)，后箱贴在它后面 (3,4)——
箱子互为墙，一个挡块等于两条停靠位。

**例 3：搁板——箱子停在墙顶，目标格在墙的正上方。**
```
倾斜前              向下倾
#######            #######
#..B..#            #.....#
#.....#            #.....#
#..T..#      →     #..*..#
#.###.#            #.###.#
#.....#            #.....#
#######            #######
```
箱子 (3,1) → (3,3)，被 (3,4) 的墙挡住，正好落在目标格上（`*` = 箱子在目标格）。
"墙顶"就是搁板：中后期关卡靠它把已经放好的箱子寄存起来，防止被后续倾斜带走。

### 2.6 边界判定（实现照抄，不用再问）

每条都由校验器实算确认（`tools/boundary_cases.py`）。

| 情形 | 倾斜方向 | 结果 |
|---|---|---|
| 箱子贴墙 | 朝墙 | **不动** |
| 箱子贴另一箱 | 朝那一箱 | **整串一起走**：前箱让出空位、后箱跟进，终位同 §2.5 例 2 |
| 箱子贴另一箱，且前箱后面是墙 | 朝那一箱 | 整串都**不动**（顶死） |
| 箱子贴挡块 | 朝挡块 | **不动**；挡块永远不会被推走 |
| 箱子经过目标格 | 任意 | **不停**，继续滑到墙/箱/挡块为止；经过的目标不计完成 |
| 箱子已在目标格上 | 任何能让它动的方向 | **被推走**，目标格变空（不锁定） |
| 一次倾斜里所有箱子都不动 | 任意 | 仍是**有效的一步**：计步、进快照栈，不判死局 |

两条最容易写错的，图示如下：

**经过目标不停**（目标在 (3,1)，箱子从 (1,2) 向右滑，直接越过去了，终点 (5,2)）：
```
倾斜前              向右倾
#######            #######
#..T..#            #..T..#
#B....#      →     #....B#
#.....#            #.....#
#######            #######
```

**目标不锁定**（箱子本来就在目标格上，向左倾就被推走，目标格空出来）：
```
倾斜前              向左倾
#######            #######
#.....#            #.....#
#..*..#      →     #B.T..#
#.....#            #.....#
#######            #######
```
`*` = 箱子在目标格上。这就是为什么最后一步最容易翻车：先放好的箱子会被下一步带走。

## 3. 操作

### 3.1 拖拽挡块
- 单指按住挡块任意位置拖动，手指与格子不要求重合偏移；松手吸附到最近格心。
- 拖动中显示虚影 + 目标格高亮，非法格标红。
- 拖动期间不接受倾斜结算（正在拖就说明还没走完这一步）。

### 3.2 倾斜触发

| 参数 | 值（度） | g 等价（`sinθ`） | 说明 |
|---|---|---|---|
| 触发角 | `M ≥ 20.5°` | 0.35g | 主分量 |
| 轴比闸门 | `M/m ≥ 2.0` | — | 输入偏离主轴 ≤26.6°；45° 斜倾被直接丢弃 |
| 回正角 | `M ≤ 5.7°` | 0.10g | 死区 |
| 回正保持 | `≥ 80ms` | — | 瞬时回正不算 |

- 方向量化：取 `|beta'|`（前后）与 `|gamma'|`（左右）中较大者为轴；轴比不足或幅值不足都**整次丢弃**，不产生斜向、不产生半步。
- 触发后立即 `armed = false`；必须满足"回正角 + 保持 80ms"才重新武装。
- 80ms 用 `performance.now()` 判定，**不要用帧数**（帧率会变）。
- **不要额外加冷却计时器**：状态机（必须回正 80ms 才能重新武装）已经是唯一节流。再叠一个"距上次触发 ≥140ms"的冷却，会把合法的快速连倾吞掉，而且两套节流必然先崩一套。
- **除零保护**：次分量 `m < 0.5°` 时视为纯轴输入，**跳过比值计算、直接通过轴比闸门**（纯轴是最标准的输入，必须能触发），绝不做除法。只有 `m ≥ 0.5°` 时才计算 `M/m`。

### 3.3 校准
- 首次进入显示"把手机平放，点一下校准"；取约 200 帧均值当零偏 `(bβ, bγ)`（单位：度），之后一律用 `(beta-bβ, gamma-bγ)`。
- 零偏存 `localStorage`，下次直接复用；设置里可重校。
- 零偏异常（平放时任一轴偏差 > 17°，≈0.3g）时提示重校，不静默接受。

### 3.4 切后台 / 锁屏 / 页面隐藏
**可见性变化时必须重置 `armed = false` 并丢弃上一帧姿态**，回来先要求回正才允许触发。
否则回到前台的第一帧会拿着旧姿态白算一步——安卓上必踩，且与"一次倾斜一次承诺"直接冲突。
页面隐藏时暂停 `requestAnimationFrame` 与传感器监听；可见后重新武装前先静默丢弃 200ms 的样本。

### 3.5 触控兜底（必须有）
- 屏幕四边或下方提供 4 个方向按钮，点一次 = 完成一次整盘结算。
- 桌面浏览器自动显示方向键映射（←↑↓→ + Z 撤销 + R 重开）。
- 兜底路径与传感器走**同一个结算入口**，不是第二套逻辑。
- 存在理由：没有传感器 / 权限被拒 / 用户不想晃手机 / 桌面测试。判定逻辑必须与倾斜完全一致。

### 3.6 撤销与重开（语义写死）

- **快照点只有一处**：每次倾斜**开始前**存一份完整快照 = 箱子集合 + 挡块格 + 已用步数。
- **撤销 = 弹出最近一份快照并整体恢复**（箱子、挡块、步数三者一起回退）。连按可一路回到开局。
- **拖拽不产生快照**。拖了三次再撤销，回到的是"上一次倾斜前"的状态，那三次拖动**全部作废**。
  这是刻意的：拖动随时可以重来、没有回退价值；如果给拖动也建快照，玩家按撤销会出现"只退挡块不退箱子"的半格状态，比不退更困惑。
- **步数只统计倾斜**：拖拽不计步、不限次数。因此恒有 `步数 == 倾斜次数 == 快照栈深度`。
- 撤销按钮在栈空时置灰（不弹提示）。从没倾斜过的一局，撤销键始终是灰的——这正确，不是 bug。
- **重开**：回到关卡初始快照，步数归零，快照栈清空。重开本身不进撤销栈。

### 3.7 传感器失败兜底

- **进关先探测**：没有 `DeviceOrientationEvent`、权限被拒、或非安全上下文 → 直接进按钮模式，顶部一行提示"未检测到重力传感器，已切换到方向键"。
- **静默无数据判失效**：挂上监听后 **3 秒内 0 个事件**即判定传感器无数据。
  这条不能省——安卓在 `http://` 下就是这个表现：**不报错、不弹窗、就是没数据**（Dev 实测）。没有它，玩家会对着不动的棋盘发愣。
- **单帧异常丢弃**：事件值 `NaN`、或相对上一帧跳变 > 90° → 丢弃这一帧，`armed` 保持不变。这是坏数据，不是玩家动作，**不能**当成一次倾斜。
- 连续 20 帧异常 → 按失效处理，切按钮模式。
- 切到按钮模式后监听不撤，玩家可随时切回倾斜操作；两种方式都能从头玩到第 12 关。
- 两种输入走**同一个结算入口**（§3.5），按钮模式不另写一套判胜负。

## 4. 关卡

### 4.1 关卡记号

```
#  墙        .  地板      B  箱子
T  目标格    K  挡块初始位    *  箱子在目标格上
```
- 每关**恰好 1 个 `K`**；挡块初始位不影响可解性（随时能拖走），只影响首帧观感。
- 一行一列，不补空格；短行按墙补齐。

### 4.2 三条设计法则（后面所有关卡都靠它们成立）

1. **一次倾斜只有一条射线能被挡块改变落点**。挡块只占一格，所以"两个箱子都要中途停"必须拆成两次倾斜。
2. **竖倾之后，每个箱子都贴底、贴箱或贴板**。所以最后一步通常是一次性把所有箱子送到位——中途放好的箱子会被后续倾斜弄走。
3. **搁板（下方是墙）能让箱子在竖倾中不动**。它是"寄存已放好的箱子"的唯一手段，也是中后期关卡的结构基础。

由此推出的陷阱形态：目标不锁定，箱子经过目标不算完成；玩家很容易在倒数第二步把箱子推离目标。

### 4.3 关卡表

12 关 = 3 教学 + 9 主线。**最少倾斜与首步容错率由校验器实测，不是估的**（`tools/report_levels.py` 可复现）。

| 关 | 名称 | 箱数 | 最少倾斜 | 其中拖拽 | 新机制 / 考点 | 首步容错 | 预估平均步数* |
|---|---|---|---|---|---|---|---|
| T1 | 撞墙即停 | 1 | 1 | 0 | 倾斜手势；滑到墙停 | 100% | 1–2 |
| T2 | 挡块接住 | 1 | 1 | 1 | 挡块当墙；走廊中段停箱 | 100% | 1–2 |
| T3 | 箱子排队 ★ | 2 | 1 | 0 | 箱子互为墙，一次倾斜解决两个 | **33%** | 1–2 |
| M1 | 横向换道 | 1 | 2 | 1 | 先落到底，再用挡块横推到目标列 | 100% | 2–3 |
| M2 | 靠右排队 | 2 | 2 | 0 | 两箱挤到同侧墙再一起下落 | 100% | 2–4 |
| M3 | 停准一格 | 1 | 2 | 1 | 挡块精确停格，差一格都不行 | 100% | 2–4 |
| M4 | 搁板 | 1 | 2 | 1 | 目标格只能从上方落入（左右都是墙），箱子必须落在墙顶 | 100% | 2–4 |
| M5 | 两箱收口 | 2 | 3 | 2 | 挡块护住一个，先处理另一个 | 100% | 3–6 |
| M6 | 先让路 | 2 | 3 | 2 | 同列两箱：不先让开上面那个就永远合不上 | 100% | 3–6 |
| M7 | 三箱散落 | 3 | 4 | 2 | 三箱错列，先顶齐再归列 | 100% | 4–8 |
| M8 | 搁板双箱 | 2 | 5 | 2 | 搁板寄存 + 挡块二次使用 | 100% | 5–9 |
| M9 | 终局 | 3 | 6 | 3 | 三箱 + 搁板 + 三次拖拽 | 100% | 6–11 |

\* 预估平均步数是"最短 × 1.5–2"的推演值，**未经真人实测**，试玩后要按实际重排。
★ **T3 是试玩第一优先验证项**：首步容错 33%、死局率 87% 两个指标都指向它，宽松备选见 §4.4。
首步容错率 = 首步所有会改变盘面的走法里，仍然解得开的比例。
「其中拖拽」= **求解器最优解**里挪了几次挡块，不计步，仅作信息（步数只统计倾斜，见 §3.6）。
该列**不含开局避让拖拽**：求解器假设挡块每步可自由放置，而正式关卡有初始 `K`；M1/M2/M4 的初始 K 会压在箱子路径上，实际游玩要先把它拖开一次。避让拖拽同样不计步，**不影响最少倾斜数（仍是 32）**。

**合计最短 32 次倾斜。**整包通关预计 5–10 分钟。

### 4.4 实测出来的两个事实

1. **几乎不会死局。** 12 关中 11 关的随机瞎按死局率是 **0%**（每关 300 次随机序列、深度 2×最优）。原因是挡块随时可重放、箱子不会被消耗、没有计时。所以这个游戏的失误代价是"变慢"，不是"废掉"。
2. **唯一的例外是 T3，死局率 87%。** 两箱在同列，一旦横向倾开就再也合不回同列（只有一个挡块）。它是教学关，会配提示箭头，且撤销只需一次点击。
   **风险标记**：如果试玩发现第 3 关劝退，把 T3 的目标从 `(3,6)(3,7)` 换成 `(3,7)(4,7)` 的宽松版本，死局率会直接掉到接近 0。

## 5. UI / 视觉

### 5.1 布局（竖屏单手）
- 顶部：左侧选关、中间关卡号 + 名称、右侧"如何玩"；步数显示在棋盘正上方。
  **不做暂停按钮**：本作无计时、无实时压力，暂停没有意义。
- 中部：7×9 棋盘，等比缩放居中，四周留 16px 安全边。棋盘是最贵的东西，占屏高 60–65%。
- 底部：撤销 / 重开 / 关卡选择 三个按钮，落在拇指区。
- 无横屏支持（手机端锁竖屏；桌面端等比缩放即可）。

### 5.2 三种形状（不靠颜色区分）
- **箱子**：实心圆角方块，亮色。
- **挡块**：空心圆环 / 菱形，最亮描边，明显区别于箱子。
- **目标格**：虚线方框，箱子在上时变成实线高亮。
- 色盲友好：形状 + 明度差异，不只靠色相。深底浅图，对比度 ≥ 4.5:1。

### 5.3 动效与反馈
- 滑动：每格 85ms（可调区间 70–100），单步总时长夹在 **120–350ms**（只走一格也至少 120ms，太快看不清落点）。
- 落点反馈：本次停住的格子高亮 **220ms**（实现口径）。**不做"顿帧冻结"**——在手机上冻结会被读成掉帧，高亮比停顿干净。
- 胜利：所有目标格同时亮起 + 关卡号翻页，不弹大窗（避免打断）。
- 拖动挡块：跟手，无延迟；非法格标红并轻微抖动。
- 倾斜指示（可选）：屏幕边缘一根细箭头提示当前解析方向，教玩家"它在往哪算"。

### 5.4 文案基调
短句、命令式，不卖萌。教学关一句话提示就够："往下倾"、"把挡块放到它前面"。
失败不存在，所以没有"你输了"这类文案。

## 8. 验收标准

| 编号 | 验收内容 | 通过标准 |
|---|---|---|
| A1 | 结算可复现 | 同一关卡 + 同一操作序列（拖拽序 + 倾斜序）回放 100 次，逐格状态 0 差异 |
| A2 | 状态不变量 | 1000 次随机局面 × 随机方向：箱子不重叠、不与挡块重叠、不越界 |
| A3 | 结算等价性 | 前序优先遍历 vs 逐格步进参考实现，1000 例结果全等 |
| A4 | 抖动不刷步 | 快速左右倾 20 次不回正，最多结算 1 次 |
| A5 | 非法拖动 | 挡块拖到墙/箱/图外，松手回原位，棋盘不变 |
| A6 | 胜利判定 | 仅全箱在目标时触发；挡块压目标不触发；动画未结束不弹 |
| A7 | 撤销语义 | 每次撤销恢复"最近一次倾斜前"的完整快照（箱子 + 挡块 + 步数）；拖拽不进快照、拖 3 次后撤销三者一起回退；连按可回开局；栈空时置灰 |
| A8 | 关卡可解 | 12 关全部可解，最短倾斜数等于 §4.3 表内数值（校验器可复现） |
| A9 | 后台恢复 | 切后台/锁屏回来第一帧不产生任何结算，必须先回正 |
| A10 | 真机协议 | Dev 的 10 分钟真机协议全过（见 `docs/TECH_SENSOR_RECON.md` §6） |
| A11 | 传感器失败兜底 | 3 秒无事件即切按钮模式并提示；单帧 NaN/跳变 > 90° 被丢弃且不消耗步数；按钮模式可完整通关 |

## 9. 测试计划

### 9.1 关卡层（不跑游戏，先测设计）
```bash
python tools/report_levels.py -v      # 12 关可解性 + 最短倾斜 + 首步容错 + 一条最优解

```
设计改动后先跑这个；关卡不可解或最短步数变了，**文档表格必须同步**，`check_doc_levels.py` 会对不上就报 MISMATCH。

脚本已自行把 stdout 切成 UTF-8，Windows 默认控制台（cp1252）不会再抛 `UnicodeEncodeError`。
若终端仍显示乱码（不是报错，是显示），在前面加 `PYTHONIOENCODING=utf-8` 即可。

### 9.2 传感器层
- 自动化：Dev 的 `spike/cdp-test.mjs`，**15 项**全过（含"超阈值只触发 1 次""阈值下抖动不增加次数""持续倾斜 2 秒不连发""45° 斜倾不触发"）。
- 真机：按 `TECH_SENSOR_RECON.md` §6 的 10 分钟协议走一遍，截图 + 诊断 JSON。

### 9.3 手动测试
1. 12 关逐关通关，记录实际步数（回填 §4.3 预估列）。
2. 每关连着做：撤销到底 → 重开 → 再做一次，状态一致。
3. 切后台 5 秒 / 锁屏 30 秒 / 接电话，回来不白算步。
4. 拖动挡块到每个非法位置，确认弹回且不缺格。
5. 关掉传感器权限，用方向键兜底通关一关。

安卓 Chrome（主）、桌面 Chrome（兜底）、iOS Safari（只求能开，不承诺手感）。
