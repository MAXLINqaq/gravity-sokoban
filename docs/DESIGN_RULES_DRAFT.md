## 0. 一句话

倾斜手机一次，所有箱子沿重力方向同时滑到撞上东西为止；你只有一个**不受重力**的挡块，用拖拽摆放它来让箱子停在你想要的位置。

本作不是"推"，是"投掷 + 挡停"。

---

## 1. 网格与地图

- 直角网格，格子整数坐标 `(x, y)`，`x` 向右、`y` 向下（屏幕坐标）。
- 关卡尺寸逐关给，竖屏推荐 `7×9` ~ `9×11`；MVP 固定同一尺寸也可，先按 `8×10` 占位。
- 每格只有一种地面类型：
  - `WALL` 墙：不可进入，箱子撞上即停。
  - `FLOOR` 地板：可进入。
  - `GOAL` 目标格：可进入，承担"箱子停在这里算完成"。
- 地图外一律按 `WALL` 处理（越界不必特殊分支）。
- 棋盘外框**不强制**是墙。允许"开口"是不可能的（地图外按墙），所以外框是否画墙只影响美术，不影响规则——但关卡作者必须理解：**最外圈永远是死的**。

**这条规则逼玩家做什么决定**：无（只是地基）。它的作用是让"箱子失控飞出棋盘"这类状态在规则上不存在，关卡因此可穷举。

## 2. 重力输入 → 一次倾斜

### 2.1 原始输入
- 读设备重力/加速度的 `(gx, gy)`，单位 `g`（1g ≈ 9.8 m/s²）。
- 平放校准：进关前"手机平放点一下校准"，取 200 帧均值作零偏 `(bx, by)`，之后一律用 `(gx-bx, gy-by)`。零偏存本地，下次进关直接复用。
- 无传感器设备（桌面浏览器）：走键盘方向键 / 屏幕方向键，视为等价的一次倾斜。

### 2.2 方向量化（防歧义）
一次倾斜只解析成 **4 个方向之一**，绝不产生斜向：

1. `|gx| ≥ |gy|` → 候选方向 = `gx>0 ? RIGHT : LEFT`，主分量 `M=|gx|`，次分量 `m=|gy|`；
2. 否则候选方向取竖直轴，`M=|gy|`，`m=|gx|`；
3. **轴比闸门**：`M/m ≥ 2.0`（等价于主分量占向量约 67% 以上）才接受；否则整次输入忽略（斜着拿手机不触发）。
4. **幅值闸门**：`M ≥ 0.35g` 才触发。

### 2.3 触发与重新武装（关键）
- 触发一次后立即 `armed = false`，**必须回正**才能再触发。
- 回正条件：`M ≤ 0.10g` 且持续 `≥ 80ms`。
- 含义：一次"拿起手机倾斜再放下"= 一步。连续抖动、来回晃都不会刷出额外步数。

**这条规则逼玩家做什么决定**：一次倾斜是不可撤回的一整步，所以玩家在倾之前必须把这一步的**全部后果**想完（哪些箱子会动、动到哪、会不会把另一个箱子的落点堵死）。这就是整个游戏的操作压力来源。

## 3. 一次倾斜的结算（可复现的核心）

方向 `d` 为 `LEFT/RIGHT/UP/DOWN` 之一。

### 3.1 结算顺序：贴着目标墙的先动
1. 对每个箱子算 `t` = 沿 `d` 到地图边缘（按 `WALL` 处理）的格数，`t` 越小越靠近"前方"。
2. 按 `t` **升序**处理；`t` 相同则按 `(y, x)` 升序处理（只影响日志可读性，不影响结果）。
3. 每个箱子沿 `d` 逐格试探，直到下一格满足任一条件就停在当前格：
   - 是 `WALL`；
   - 已被本次结算中**已停下**的箱子占据；
   - 是挡块（见 §4）。
4. 处理完最后一个箱子，得到新状态。

### 3.2 为什么是这个顺序（等价性说明）
同一方向上箱子不能互相超越，所以"离终点最近的先走"与"同时滑动"结果**逐格一致**，且天然处理了"前面的箱子挪开、后面的箱子跟进填满"的情形。反过来（从后往前）会得到错误结果。

因此实现方**不需要**写迭代式滑动或多轮求解，一趟升序遍历即为规则定义本身。

### 3.3 明确禁止（避免歧义）
- 箱子**不能推动**箱子：箱子对箱子只存在"停住"，不存在"传递推力"。
- 箱子**不能**被推出地图。
- 一次倾斜中每个箱子最多移动一次、只沿 `d` 直线移动。

**这条规则逼玩家做什么决定**：箱子是"可移动的墙"。你先让 A 箱垫住 B 箱的路线，还是先让 B 箱让开，顺序错了就再也回不来（只能撤销/重开）。

## 4. 挡块（唯一的自由变量）

- 全图 **恰好 1 个**挡块，占 1 格。
- **不受重力**：任何倾斜都不移动它。
- **可拖动**：手指拖到任意合法空格，松手即生效（吸附到格心，与箱子一致的 40px 手感口径不作硬要求，但必须格对齐）。
- 合法落点：地图内、非 `WALL`、非箱子当前格。`GOAL` 格**允许**（见 4.3）。
- 非法落点：拖动中预览变红，松手弹回原位，**不改变任何状态、不消耗任何动作**。
- 拖动只能在"静止态"进行（结算动画期间输入锁定，见 §6）。
- 挡块**不可被推动**：箱子撞上挡块就停在相邻格。

### 4.1 挡块站在目标格上
- 允许；该目标格视为"未完成"，挡块移开后才可能被箱子占据。
- 规则上不加任何提示性惩罚，交给玩家自己看出来。

### 4.2 允许 / 不允许
| 操作 | 允许 |
|---|---|
| 挡块拖到目标格 | ✅ |
| 挡块拖到箱子身上 | ❌ 弹回 |
| 挡块拖到墙里 | ❌ 弹回 |
| 挡块拖到地图外 | ❌ 弹回 |
| 箱子停在挡块旁 | ✅ |
| 挡块被箱子挤走 | ❌ 不存在此规则 |

**这条规则逼玩家做什么决定**：挡块是唯一能"在走廊中间制造一堵墙"的东西。每次倾斜前都要回答：**这一格放哪，才能让不该动的箱子不动，让该停的箱子刚好停住**。

## 5. 胜负

### 5.1 胜利（推荐口径）
- 判定时机：一次结算的动画播放完毕后（同一帧内判定即可，不允许在动画中途提前弹胜利）。
- 条件：**箱子总数 > 0** 且 **每个箱子所在格 ∈ 目标格集合** 且 **箱子数 == 目标格数**。
- 挡块压在目标格上不构成完成（该格没有箱子）。

### 5.2 失败
- MVP **不设失败**：没有计时、没有步数上限、箱子不可能掉出去。
- 不提供自动死局检测（"这局已经打不完了"）。理由：死局判定容易误报，代价是玩家偶尔要多走一步才意识到，但撤销/重开随时可用，体验损失极小。
- 提供：撤销（回退最近一次**倾斜**，挡块位置一并回退）、重开本关。

### 5.3 未拍板的两种变体（用户选则本表改）
| 变体 | 规则差异 | 代价 |
|---|---|---|
| B：滑进洞里消失 | `GOAL` 改为 `PIT`，箱子进入即消失并计数；胜利 = 箱子全部消失 | 更简单，但箱子被"消耗"掉，§3.2 的垫箱策略大量失效，难度上限掉一档 |
| C：目标格吸住箱子 | 箱子进入 `GOAL` 立即锁死、变为障碍 | 更容易，但"吸住后算不算墙"要新增规则，且会让部分关卡退化成"一路推到底" |

---

## 6. 输入时序

- 结算动画：每格 `70–100ms`（默认 85ms），总时长上限 `350ms`。
- 动画期间：**禁止**拖动挡块、禁止新的倾斜触发（传感器信号缓存丢弃，不排队）。
- 动画结束 + `40ms` 缓冲后解锁输入，并重新武装倾斜检测（见 2.3；仍在倾斜姿态则保持未武装）。

## 7. 关卡记号（保证可复现）

单文件 ASCII，每行一列格子，行首行尾不补空格：

```
#  墙
.  地板
B  箱子（起始）
T  目标格
K  挡块（起始，全图恰好 1 个）
*  箱子已在目标格上（等价于 B+T 同格）
```

例：

```
########
#......#
#.B..T.#
#..K...#
#......#
########
```

同一记号 + 同一操作序列（`d` 倾斜序列 + 挡块拖动序列）必须得到逐格一致的状态序列。

### 7.1 三个教学微关卡（草案，验证规则确实能跑通）

- **T1「撞墙即停」**：单箱、单目标、无挡块作用；玩家先感受"一次倾斜走到底"。
- **T2「挡块是你的墙」**：目标在走廊中段，只靠墙永远过站，必须把挡块放在中间格接住箱子。
- **T3「先让谁走」**：两箱同一走廊，必须先倾一次让前箱让位，否则后箱被自己人卡死；教"顺序"和"撤销"。

## 8. 验收点（不写代码也能测）

| 编号 | 验收内容 | 通过标准 |
|---|---|---|
| A1 | 复现性 | 录制的操作序列回放 100 次，逐格状态 0 差异 |
| A2 | 不变量 | 1000 次随机局面 × 随机方向：箱子不重叠、不与挡块重叠、不越界 |
| A3 | 结算等价 | 前端优先遍历结果 vs 逐格步进参考实现，1000 例全等 |
| A4 | 抖动不刷步 | 快速左右倾 20 次（不回正），最多结算 1 次 |
| A5 | 非法拖动 | 挡块拖到墙/箱/图外，松手回原位，棋盘状态不变 |
| A6 | 胜利判定 | 仅全箱在目标时触发；挡块压目标不触发；动画未结束不弹窗 |
| A7 | 撤销粒度 | 每次撤销回退一格倾斜（含挡块位置），连按可回到开局 |

## 10. 调参入口（给实现，都给区间）

| 参数 | 默认 | 区间 | 调它将改变 |
|---|---|---|---|
| 倾斜触发幅值 | 0.35g | 0.30–0.40 | 太低误触发、太高要甩手腕 |
| 回正阈值 | 0.10g | 0.08–0.15 | 太高难重新武装，连环操作变卡 |
| 回正持续 | 80ms | 50–150 | 同上，抖手玩家可调高 |
| 轴比闸门 | 2.0 | 1.5–2.5 | 低=斜着拿也触发（易错），高=必须端平（易累） |
| 每格动画 | 85ms | 70–100 | 观感；超过 100ms 垫箱预判会看不清 |
| 总动画上限 | 350ms | 300–450 | 长走廊的等待感 |
